## ۱) یافته‌های تحلیل فایل‌ها (مبنای طراحی)

**کدینگ محک (۴ سطح):**
- ۱۱ گروه (کد ۱ رقمی) → ۴۸ حساب کل (۳ رقمی، با «نوع دائم/موقت» و «ماهیت بدهکار/بستانکار») → ۱۵۰ معین (۳ رقمی، همه «تعریف معین مستقل») → **۷۹۵ تفصیلی** (۶ رقمی).
- انواع تفصیلی: اشخاص ۱۱۹ | کالاها ۵۲۳ | هزینه‌ها ۷۶ | سایر ۲۹ | درآمدها ۱۷ | انبارها ۱۵ | بانک‌ها ۱۳ | صندوق‌ها ۲.
- کد حساب در سند = **۱۲ رقم**: `کل(۳) + معین(۳) + تفصیلی(۶)` — مثال: `206001501012` = موجودی نقد ← بانک‌ها ریالی ← ملت ۹۹۵۵.

**دفتر روزنامه:**
- **۱٬۵۳۰ سند / ۵٬۸۶۴ آرتیکل** از ۱۴۰۵/۰۱/۰۱ تا ۱۴۰۵/۰۴/۲۱ + ۱ سند مورخ ۱۴۰۴/۰۳/۳۱ (ش‌سند ۲۹۷۹).
- ساختار ردیف: `تاریخ | ش عطف | ش سند | کد حساب ۱۲رقمی | نام کامل حساب | بدهکار | بستانکار`.
- بعد از آرتیکل‌های هر سند، یک ردیف با «کد حساب خالی» = **شرح سند** (مثل «(2979) کارمزد بانک (239)...») — ۱٬۵۳۱ ردیف شرح.
- ۷۹۱ کد حساب یکتا استفاده شده؛ همه ۱۲ رقمی.
- محک **موجودی دائمی** می‌زند: هر فروش = سند فروش (Cr `601001…`) + سند بهای تمام‌شده (Dr `801…` / Cr `202001300xxx` به تفکیک تک‌تک کالاها). فروش per-invoice است ولی COGS per-product — پس **تعداد/فی واحد در روزنامه نیست**، فقط مبلغ.
- ⚠️ **۳۷ سند نامتراز** با اختلاف ۱ تا ~۱۰۰ ریال (کسر هزار محک) + مبالغ بعضاً **اعشاری**.
- جمع بدهکار کل: ۵۰۹٬۹۸۶٬۴۳۷٬۷۶۴٫۶۸ ریال.

## ۳) تغییرات لازم در برنامه (فیلدها/آپشن‌های جدید)

### ۳.۱ — دیتابیس (`server/db.js` — همه با `ensureColumn` idempotent)

```js
// نگاشت موجودیت‌های عملیاتی به کدینگ (خالی = رفتار قدیم)
ensureColumn('customers',  'coa_code', 'TEXT');   // تفصیلی دریافتنی شخص
ensureColumn('suppliers',  'coa_code', 'TEXT');   // تفصیلی پرداختنی شخص
ensureColumn('products',   'coa_code', 'TEXT');   // تفصیلی موجودی کالا (202001300xxx)
ensureColumn('banks',      'coa_code', 'TEXT');   // 206001501xxx
ensureColumn('cash_boxes', 'coa_code', 'TEXT');   // 206002500xxx
ensureColumn('persons',    'coa_code', 'TEXT');
ensureColumn('products',   'needs_qty', 'INTEGER DEFAULT 0'); // پرچم «تعداد از محک نیامده»
// ردیابی منبع سند وارداتی
ensureColumn('journal_entries', 'src_system', 'TEXT');  // 'mahak'
ensureColumn('journal_entries', 'src_doc_no', 'TEXT');  // ش سند محک
ensureColumn('journal_entries', 'src_atf',    'TEXT');  // ش عطف محک
// درخت کدینگ: chart_of_accounts باید parent_code و level و nature داشته باشد (اگر از فاز B موجود نیست)
ensureColumn('chart_of_accounts', 'parent_code', 'TEXT');
ensureColumn('chart_of_accounts', 'level', 'INTEGER DEFAULT 0'); // 1=گروه 2=کل 3=معین 4=تفصیلی
ensureColumn('chart_of_accounts', 'nature', 'TEXT');             // بدهکار/بستانکار
ensureColumn('chart_of_accounts', 'tafsili_type', 'TEXT');       // اشخاص/کالاها/بانک‌ها/...
```

### ۳.۲ — لایهٔ نگاشت حساب‌های کنترلی: فایل جدید `server/lib/coa-map.js`

همهٔ کدهای hardcode شده در route ها (`1103`, `2101`, `1106`, `1101`, `1102`, `6104`, `2104`, `4101`, ...) از این به بعد از این لایه خوانده شوند؛ مقادیر در جدول `settings` با پیش‌فرضِ کدهای قدیمی (تا نصب‌های فعلی نشکنند):

```js
// server/lib/coa-map.js
const DEFAULTS = {
  coa_receivable_moein: '203004',   // حساب‌های دریافتنی تجاری (والد تفصیلی مشتریان)
  coa_payable_moein:    '501002',   // حساب‌های پرداختنی تجاری (والد تفصیلی تأمین‌کنندگان)
  coa_sales:            '601001960001', // فروش محصولات
  coa_sales_discount:   '601004960007', // تخفیفات فروش
  coa_cogs:             '801001',   // بهای تمام‌شده (والد؛ آرتیکل per-product به تفصیلی کالا در 202 می‌خورد)
  coa_inventory_moein:  '202001',   // موجودی کالای ساخته‌شده (والد تفصیلی کالاها)
  coa_cash_default:     '206002500001', // صندوق مرکزی
  coa_bank_default:     '206001',   // والد بانک‌ها
  coa_adjustment:       '906001',   // اصلاحات و تعدیلات (تعدیل کسری ورود)
  coa_payroll_expense:  '701001',
  coa_misc_persons:     '204001'    // سایر دریافتنی‌ها — اشخاص متفرقه
};
function acct(db, key){ /* settings lookup با fallback به DEFAULTS؛ اگر settings خالی و DB قدیمی است کد قدیمی (1103...) برگردان */ }
module.exports = { acct, DEFAULTS };
```

**قانون:** روی دیتابیس تازهٔ محک این کلیدها در settings ست می‌شوند؛ روی دیتابیس‌های قدیمی ست نمی‌شوند و همه‌چیز مثل قبل با 1103/2101/... کار می‌کند — **backward compatible**.

نقاط تزریق (همهٔ جاهایی که کد حساب hardcode است): `routes/invoices.js` (فروش/تخفیف/دریافتنی)، `routes/accounting.js` (settlements، vouchers، statement)، `routes/purchases.js`، `routes/expenses.js`، `routes/payroll.js`، `routes/production.js`، `db.js` (resolveCashAccount → اول `coa_code` رکورد بانک/صندوق، بعد fallback فعلی).

### ۳.۳ — تفصیلی‌ساز خودکار برای موجودیت‌های جدید

از این به بعد وقتی مشتری/تأمین‌کننده/محصول/بانک/صندوق جدید در ترنم ساخته می‌شود، اگر DB در «حالت محک» باشد (کلید `coa_mode=mahak` در settings):
1. کد تفصیلی بعدی از بازهٔ همان نوع تخصیص یابد (اشخاص از `1000xx`+، کالاها از `3003xx`+... با MAX موجود + 1 و جدول number_sequences برای اتمی بودن).
2. ردیف تفصیلی در `chart_of_accounts` با parent معینِ نگاشت ساخته شود.
3. `coa_code` رکورد ست شود. حذف رکورد = غیرفعال‌شدن حساب (نه حذف، اگر گردش دارد).

### ۳.۴ — سند خودکار بهای تمام‌شده (تصمیم ۸)

در `routes/invoices.js` داخل همان `db.transaction` فاکتور رسمی، اگر `feature_cogs_voucher=1`:
```
Dr  <coa_cogs>                      Σ(qty × cost هر ردیف)
Cr  <products.coa_code هر کالا>     qty × cost همان کالا   (به تفکیک)
```
- اگر `cost=0` بود آرتیکل آن کالا زده نمی‌شود (و در گزارش «کالاهای بدون بها» می‌آید).
- حذف/برگشت فاکتور، سند COGS را هم دقیقاً معکوس می‌کند (در همان مسیرهای موجود reverse).
- تبدیل پیش‌فاکتور→رسمی: سند COGS در لحظهٔ رسمی‌شدن.

### ۳.۵ — UI (همه در `server/public/index.html`)

- پنل جدید «⚙️ نگاشت کدینگ» در تنظیمات حسابداری: نمایش/ویرایش کلیدهای coa-map + کلید `feature_cogs_voucher`.
- فرم مشتری/تأمین‌کننده/محصول/بانک/صندوق: نمایش readonly «کد تفصیلی» + دکمهٔ «اتصال به حساب موجود» (برای رکوردهای قدیمی بدون coa_code).

### الگوریتم (دقیق):

```text
فاز A — کدینگ:
 1. شیت «گروه حساب ها» → سطح۱ (کد ۱ رقمی، نوع=دارايي/بدهي/...)
 2. «حسابهای کل» → سطح۲ (کد ۳رقمی، parent=گروه اول کد، nature=ماهیت)
 3. «حسابهای معین» مستقل‌اند؛ معین واقعی از «کدهای ۶ رقمی ابتدای اسناد» ساخته می‌شود:
    برای هر کد ۱۲رقمی دیده‌شده در روزنامه: kol=c[0..3), moein=c[3..6), taf=c[6..12)
    سطح۳: کد kol+moein، نام از شیت معین (کد moein) — parent=kol
    سطح۴: کد ۱۲رقمی کامل، نام = عنوان تفصیلی از شیت تفصیلی (کد taf) — parent=سطح۳
    ⚠ تفصیلی‌هایی که در روزنامه نیامده‌اند هم از شیت تفصیلی ساخته شوند (زیر معین پیش‌فرضِ نوعشان
      طبق نگاشت نوع→معین: اشخاص→203004/501002 هر دو نه! ⇒ زیر «معینِ پرتکرارِ همان تفصیلی در روزنامه»؛
      اگر اصلاً گردش ندارد: اشخاص→203004، کالاها→202001، بانک‌ها→206001، صندوق‌ها→206002،
      هزینه‌ها→معین 504 پرمصرف مربوط، درآمدها→601001، انبارها/سایر→ذیل 906001 نمی‌رود؛ «ساير»→204001)
 4. نام حساب آرتیکل = «عنوان تفصیلی» (نه رشتهٔ کامل ' - ' دار).

فاز B — کالاها (تصمیم ۶):
 برای هر تفصیلی نوع «کالاها»: INSERT products
   name=عنوان، code=کد تفصیلی، coa_code=202001+taf (یا معینی که در روزنامه دیده شد)،
   cost = ارزش سند افتتاحیه ÷ تعداد؟ تعداد نداریم ⇒ cost=0، stock=0، needs_qty=1،
   note='ارزش افتتاحیه محک: X تومان'
 (ارزش افتتاحیه از آرتیکل‌های سند شماره 1 مورخ 1405/01/01 استخراج و در note/گزارش ثبت می‌شود)

فاز C — بانک‌ها/صندوق‌ها:
 هر تفصیلی «بانک‌ها» → INSERT banks(name, coa_code) | «صندوق‌ها» → cash_boxes(name, coa_code)

فاز D — اسناد:
 گروه‌بندی ردیف‌ها بر اساس «ش سند» به‌ترتیب ظاهر:
   - ردیف‌های با کد = آرتیکل: amount=round(rial/10)؛ هر دو ستون صفر ⇒ ردشو
   - ردیف بدون کد = شرح سند (توضیح entry)
 برای هر سند:
   Σبدهکار و Σبستانکار (بعد از ÷۱۰ و گرد) مقایسه؛ اگر |اختلاف|>0:
     آرتیکل تعدیل به coa_adjustment با شرح «تعدیل کسری ورود از محک (سند X)» سمت کسری
   INSERT journal_entries(date, description=شرح, src_system='mahak',
     src_doc_no=ش‌سند, src_atf=عطف, ref_type='mahak_import')
   INSERT journal_lines(account_code=کد۱۲رقمی, account_name=عنوان تفصیلی, debit, credit)
 ترتیب: تاریخ صعودی، سپس ش‌سند صعودی. سند 1404/03/31 عیناً وارد شود (تصمیم ۷).

فاز E — راستی‌آزمایی داخل همان اجرا (اگر هرکدام شکست: rollback کامل):
 ✔ تعداد سند == 1,530 (or 1,531 با شمارش دقیق) و آرتیکل == 5,864 + خطوط تعدیل
 ✔ تراز آزمایشی balanced==true
 ✔ Σبدهکار ترنم == round(509,986,437,764.68/10) ± مجموع تعدیل‌ها (گزارش عددی)
 ✔ گردش هر حساب کل (14 کل) == محک ÷۱۰ (جدول مقایسه در گزارش)
 ✔ هیچ account_code خارج از chart_of_accounts
 خروجی: mahak-import-report.md (آمار + ۳۷ تعدیل + کالاهای needs_qty + هر هشدار)
```

### نکات ضد-باگ (از تحلیل واقعی داده):
- مبالغ ممکن است جداکنندهٔ هزارگان یا اعشار داشته باشند → پارس با `parseFloat(String(v).replace(/,/g,''))`.
- نام‌ها فاصله‌های ابتدایی دارند (`'  مشتري عمومي'`) → `trim()`؛ ی/ک عربی→فارسی نرمال‌سازی برای جستجو.
- «ش سند» یکتاست ولی ترتیب فایل تضمین نیست → مرتب‌سازی صریح.
- ÷۱۰ باید **در سطح آرتیکل** انجام و گرد شود، سپس تعدیل — نه گرد کردن جمع (وگرنه تعدیل‌ها غلط می‌شوند).
- import باید **idempotent** باشد: اگر `src_system='mahak'` قبلاً در DB هست → اجرا متوقف شود مگر `--force-wipe-mahak`.

## ۷) کارهای پس از مهاجرت (خارج از این سند)
