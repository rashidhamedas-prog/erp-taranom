# اسکیل طراحی UI — ERP ترنم

## ⛔ هشدار: توصیه‌های ژنریک را اجرا نکن

راهنماهای رایج طراحی با Cursor فرض می‌کنند پروژه **React/Next.js + TypeScript + Tailwind + Storybook + Material You** است. **این پروژه هیچ‌کدام نیست.** پیش از هر کار این تطبیق‌ها را بپذیر:

| توصیهٔ ژنریک | در این پروژه |
|---|---|
| React/Next.js Server Components | ❌ — **vanilla HTML/CSS/JS در یک فایل** `server/public/index.html` |
| Tailwind CSS | ❌ — CSS دستی با **CSS Custom Properties** (توکن‌های `:root`) |
| Storybook / atomic design folders | ❌ — بدون build؛ کامپوننت‌ها همان کلاس‌های CSS موجودند |
| Material You / Inter / dynamic color | ❌ — تم **«زمرد مدرن» (روشن) + «شب مخملی» (تاریک)**، فونت **Vazirmatn**، RTL |
| `next/image`, lazy import, React.memo | ❌ — بدون bundler؛ بهینه‌سازی = CSS سبک + عدم reflow |
| `.cursorrules` با قوانین React/TS | ⚠️ — قوانین این سند جایگزین است |
| افزودن پکیج/CDN فونت/آیکون | ❌ — **اپ آفلاین‌فرست است**؛ هیچ منبع خارجی runtime اضافه نکن |

**اصولِ درستِ آن راهنما (Design System، Design Tokens، Chain-of-Thought، حلقهٔ بهبود، دسترس‌پذیری، تصویر مرجع) معتبرند — فقط باید روی استک زیر پیاده شوند.**

---

## ۱. استک و محدودیت‌های واقعی

- **فرانت:** تک‌فایل `server/public/index.html` (CSS در `<style>`، HTML، JS در `<script>`). بدون کامپایل، بدون npm فرانت.
- **جهت:** کل برنامه **RTL فارسی**؛ فونت **Vazirmatn** (از منبع موجود پروژه — CDN جدید اضافه نکن).
- **پلتفرم‌ها:** وب + دسکتاپ (Electron) + اندروید (WebView، nodejs-mobile). طرح باید در هر سه و آفلاین کار کند.
- **پول:** ریال؛ نمایش با `fmt()` (جداکنندهٔ هزارگان). ورودی‌های عددی خودکار به انگلیسی (`toEnDigits`).
- **اسکریپت صفحه:** اگر فایل JS جدا اضافه می‌کنی، **حتماً IIFE-wrap کن** (`(function(){ ... })();`) — متغیر سراسری `const x` کل اسکریپت صفحه را می‌شکند (سابقهٔ باگ login داریم).
- **بدون وابستگی جدید:** آیکون/فونت/چارت را از همان چیزی که پروژه دارد استفاده کن.

---

## ۲. Design Tokens (منبع حقیقت — همیشه از این‌ها استفاده کن، هرگز رنگ hardcode نکن)

توکن‌ها روی `:root` (روشن) و `html[data-theme="dark"]` (تاریک) تعریف شده‌اند. **هر عنصر جدید باید فقط از این متغیرها رنگ بگیرد** تا هر دو تم و چاپ خودکار درست شوند.

**زمرد مدرن (روشن):**
```
--purple:#1A5C38  --purple2:#2E7D4F  --purple-light:#EAF4EE   (رنگ اصلی/برند)
--gold:#C9A843    --gold-light:#FDF3D9                        (لهجه/طلایی)
--green:#059669  --red:#DC2626  --orange:#D97706  --blue:#2563EB  (معنایی)
--bg:#F5F8F4  --card:#FFFFFF  --text:#12271C  --muted:#5F7268  --border:rgba(18,39,28,.11)
--on-accent:#FFFFFF                                           (متن روی دکمهٔ رنگی)
--th-bg  --row-hover  --well  --input-bg  --shadow-card  --side-bg  --hero
--ok-bg/--ok-fg  --bad-bg/--bad-fg  --amber-bg/--amber-fg  --info-bg/--info-fg  (چیپ وضعیت)
```
**شب مخملی (تاریک) — همان کلیدها با مقادیر تاریک** (مثلاً `--purple:#3DDC8C`، `--bg:#0D1512`، `--on-accent:#04150C`).

قواعد:
- متن روی دکمهٔ برند = `var(--on-accent)` (در تاریک روشن نیست، تیره است — دقت کن).
- وضعیت‌ها را با جفت `--ok/bad/amber/info-bg/fg` بساز، نه رنگ خام.
- سایه = `var(--shadow-card)`؛ حاشیه = `var(--border)`؛ زمینهٔ ورودی = `var(--input-bg)`.

## ۳. کامپوننت‌ها و هلپرهای موجود (استفادهٔ مجدد کن، از نو نساز)

- **دکمه:** کلاس `.btn` (+ واریانت‌های رنگی موجود). حالت‌های hover/active/focus را حفظ کن.
- **مودال:** `.overlay`/`.modal` + `openModal(type)` / `closeModal(type)` (کلاس `.open`، بستن با کلیک backdrop). فیلدهای فرم با پیشوند موجودیت (`c-` مشتری، `o-` سفارش، `inv-` فاکتور).
- **تب/صفحه:** `showPage(p)`، `ROUTES`، حسابداری با `acc-nav.js` + `loadAccTab` + توابع `renderXxxTab()`.
- **جدول:** از `--th-bg`, `--row-hover` استفاده کن؛ ارقام با `font-variant-numeric:tabular-nums` و `fmt()`.
- **چیپ وضعیت / بَج:** `.badge` با جفت‌توکن `--ok/bad/amber/info`.
- **جعبهٔ نکته/هشدار:** `--tip-bg` / `--warnbox-bg`.
- **اعلان:** `toast(...)` موجود.
- **پول/عدد:** نمایش `fmt(n)`؛ ورودی `toEnDigits` (خودکار روی فیلدهای عددی).

---

## ۴. قواعد ظاهریِ ویژهٔ این پروژه

- **RTL:** چیدمان راست‌به‌چپ؛ از منطق `margin-inline`/`padding-inline` و flex/grid با `gap` استفاده کن، نه left/right ثابت.
- **هر دو تم را بساز و تست کن:** هیچ‌وقت فقط روشن را نگاه نکن؛ در «شب مخملی» هم کنتراست و خوانایی را چک کن.
- **چاپ (فاکتور):** استایل `@media print` باید همیشه روشن/رسمی باشد و کروم ناوبری را مخفی کند؛ عناصر جدیدِ داخل فاکتور را با print هماهنگ کن.
- **تراکم داده:** این یک ERP است — جدول‌ها و فرم‌های پرمحتوا. فضای سفید متعادل، نه هیرویِ غول‌پیکر. خوانایی و اسکن‌پذیری اولویت است.
- **جدول عریض:** داخل کانتینر `overflow-x:auto` تا بدنهٔ صفحه افقی اسکرول نشود.

---

## ۵. دسترس‌پذیری و ریسپانسیو (الزامی)

- **هدف لمسی ≥ ۴۴px** (مدیر بخش کف کارگاه + اندروید). دکمه‌های تأیید بزرگ.
- **focus قابل‌رؤیت** روی همهٔ عناصر تعاملی؛ HTML معنایی (`button` نه `div` کلیک‌شونده)؛ برچسب برای دکمه‌های فقط‌آیکون.
- **کنتراست ≥ 4.5:1** در هر دو تم.
- **ناوبری کیبورد** + `prefers-reduced-motion` را رعایت کن.
- **بریک‌پوینت‌ها:** موبایل (~۳۲۰)، تبلت، دسکتاپ، WebView اندروید. سایدبار جمع‌شونده؛ واحدهای نسبی؛ `max-width:100%` روی تصاویر.

## ۶. روشِ کار با Cursor (اصولِ درستِ راهنما، تطبیق‌یافته)

### الف) بریفِ ساختاریافته بده (به‌جای «یک فرم بساز»)
قالب پیشنهادی برای هر درخواست UI در این پروژه:
```
صفحه/عنصر: <مثلاً «تب گزارش مغایرت بانکی در پوستهٔ حسابداری»>
تم: زمرد مدرن + شب مخملی (هر دو، فقط از توکن‌های :root)
الگوها: از .btn / .overlay+openModal / جدول --th-bg / .badge موجود استفاده کن
RTL + Vazirmatn + fmt() برای ریال + toEnDigits برای ورودی عدد
حالت‌ها: loading، خالی (empty state)، خطا (toast)، موفق
دسترس‌پذیری: هدف لمسی ۴۴px، focus، کنتراست هر دو تم
ریسپانسیو: موبایل/تبلت/دسکتاپ/اندروید؛ جدول در overflow-x:auto
ادغام: مسیر ROUTES + renderXxxTab + loadAccTab؛ اگر فایل JS جدا شد IIFE-wrap
چاپ: اگر سند مالی است، @media print روشن/رسمی
```

### ب) Chain-of-Thought بخواه
«مرحله‌به‌مرحله: ۱) الگوها/توکن‌های موجودِ قابل‌استفاده را فهرست کن ۲) سلسله‌مراتب عناصر ۳) حالت‌ها و انیمیشن ۴) سپس کد را در همان index.html با همان سبک بنویس.»

### ج) حلقهٔ بهبود (v1→v5)
v1 ساختار و توکن‌ها → v2 حالت‌های hover/active/focus → v3 ریسپانسیو → v4 empty/loading/error → v5 دسترس‌پذیری + تست تم تاریک + چاپ.

### د) تصویر مرجع
اگر تصویر مرجع (Figma/Dribbble) دادی: «این طرح را با **توکن‌های موجود پروژه** نزدیک‌سازی کن — رنگ‌ها را به `--purple/--gold/...` نگاشت کن، نه رنگ خام؛ RTL و Vazirmatn را حفظ کن.»

## ۷. نمونهٔ پرامپت آمادهٔ این پروژه

```
نقش: مهندس ارشد UI روی ERP ترنم (تک‌فایل vanilla، RTL، تم زمرد مدرن/شب مخملی).
بساز: تب «صورت مغایرت بانکی» داخل پوستهٔ حسابداری.

طراحی:
- کارت‌های خلاصه بالا (مانده دفتر، مانده بانک، اختلاف) با --card/--shadow-card
- جدول اقلام باز با --th-bg/--row-hover، ارقام tabular-nums + fmt()
- چیپ وضعیت هر قلم با --ok/amber/bad
- دکمهٔ «تولید سند اصلاحی» با .btn برند (--on-accent)

تعامل:
- فیلترهای بازه تاریخ (جلالی رشته‌ای)، ورودی مبلغ با toEnDigits
- حالت خالی: «موردی برای تطبیق نیست»؛ خطا: toast

الزامات:
- فقط توکن‌های :root؛ هر دو تم تست شود؛ RTL
- مسیر ROUTES['acc-bank-recon'] + renderBankReconTab() + dispatch در loadAccTab
- ادغام با API واقعی (createJournalEntry برای سند اصلاحی)
- بدون وابستگی/CDN جدید؛ اگر JS جدا شد IIFE-wrap
خروجی: بلوک HTML + CSS (با توکن) + JS داخل همان index.html، هماهنگ با سبک موجود.
```

## ۸. ضدالگوها (اجتناب کن)

- رنگ hardcode (`#6750A4`, `bg-white/80`)، فونت Inter، ظاهر Material — با هویت پروژه نمی‌خواند.
- افزودن React/Tailwind/Storybook/پکیج/CDN — ممنوع (اپ آفلاین تک‌فایل).
- طراحیِ فقط‌روشن (تم تاریک را فراموش نکن) و هیرویِ غول‌پیکر در یک ERP دادـه‌محور.
- متغیر سراسری در فایل JS صفحه بدون IIFE.
- `left/right` ثابت به‌جای منطق RTL.
