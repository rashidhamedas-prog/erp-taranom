# تصمیم‌های قفل‌شده — دسکتاپ بومی + فروش لایسنسی (OEM / White-label)

تاریخ قفل: ۱۴۰۵/۰۷/۰۵ · مالک تصمیم: نمایندهٔ پروژه (دستور «بهترین انتخاب‌ها»)  
والد: [`NATIVE-WINDOWS-DESKTOP-ARCHITECTURE.md`](./NATIVE-WINDOWS-DESKTOP-ARCHITECTURE.md)

## ۱) مدل تجاری

| لایه | نقش | مثال فعلی |
|---|---|---|
| **سازنده / صادرکننده لایسنس** | هویت حقوقی محصول، امضای کد، کلید Ed25519 لایسنس، کانال update | شرکت سازنده (TAP / رایان) — قابل پیکربندی |
| **برند تجاری محصول (SKU)** | نام نصب‌کننده، آیکون، رنگ، `appId`، متون UI قابل تعویض با Brand Pack | فعلاً «ERP Taranom»؛ فروش بعدی با Brand Pack جدا |
| **مستأجر / مشتری نهایی** | دادهٔ کسب‌وکار، کاربران سازمانی، pairing به مرکز خودش | پوشاک ترنم (نصب اول) |

قواعد:
- کد و موتور دامنه **یکبار**؛ برند فقط از Brand Pack + لایسنس (نه fork مخزن).
- لایسنس به **سازنده** وابسته است نه به نام نمایشی UI.
- هر فروش OEM: Brand Pack + گواهی لایسنس مشتری + (اختیاری) مرکز اختصاصی یا سهمیه دستگاه.

## ۲) ADRهای قفل‌شده

| شناسه | تصمیم قفل | دلیل |
|---|---|---|
| ADR-01 UI | **.NET 8 LTS + WPF** (نه WinUI3 برای v1) | RTL/گرید/چاپ بالغ؛ مناسب ERP مالی |
| ADR-03 دامنه | **Primary = Headless Node Domain Host** (Named Pipe)؛ Fallback = پورت تدریجی C# با golden parity | سازگاری sync با مرکز/اندروید؛ مسیر فروش لایسنس سریع‌تر؛ Full-C# از روز اول ریسک مالی غیرقابل‌قبول برای SKU تجاری |
| ADR-02 داده | SQLite محلی per-install؛ اسکیما مشترک با مرکز | بدون سرویس DB جدا برای تک‌کاربره |
| ADR-04 sync | قرارداد فعلی outbox/replay بدون تغییر wire | اندروید و مشتری‌های موجود نشکنند |
| ADR-06 لایسنس | Ed25519 آفلاین + فعال‌سازی دستگاه؛ **بدون heartbeat اجباری**؛ grace پس از expiry = **۳۰ روز فقط‌خواندنی برای گزارش، نوشتن بسته** (قابل تنظیم در claims) | فروش لایسنسی + کار آفلاین |
| ADR-07 بسته | Installer امضاشده + کانال update جدا؛ Electron فعلی = **پل تجاری موقت** تا GA بومی | EXE امروز قابل تحویل؛ بومی مسیر نهایی |
| ADR-08 موجودی/اعتبار | تا محصول‌سازی سهمیه: **پذیرش مشروط + تعارض انسانی**؛ مسیر B2B credit جدا می‌ماند؛ سهمیه دستگاه در editionهای OEM اختیاری | جلوگیری از oversell خاموش در GA بومی (P0 sync gap) |
| ADR-09 نصب | **per-machine** برای SKU لایسنسی (فعال‌سازی پایدارتر)؛ مسیر داده `%ProgramData%\<BrandId>\` | کنترل صندلی/فعال‌سازی |
| ADR-10 Brand Pack | فایل/پوشهٔ `branding/` در بیلد: `productName`, `appId`, `publisherName`, icons, splash colors, help title — بدون تغییر منطق | فروش با نام تجاری دیگر |

## ۳) پل تحویل فعلی (تا GA بومی)

- بیلد **Electron 2.x** (کد موجود `desktop/`) به مسیر `D:\proje\ERP EXE` تحویل می‌شود.
- این بیلد **محصول نهایی بومی نیست**؛ مسیر نهایی همان ADR-01/03 است.
- هر رلیز پل: نسخه semver، امضا، کپی Setup + unpacked + checksum در `ERP EXE`.

## ۴) بعدی فوری پس از این قفل

1. فاز ۰ fixture + `schema_hash` + OPERATION-CONTRACT  
2. اسکلت `win-native/` + Domain Host pipe  
3. Brand Pack schema در بیلد Electron و آیندهٔ WPF  
4. گواهی OV سازنده (نه فقط self-signed مشتری)
