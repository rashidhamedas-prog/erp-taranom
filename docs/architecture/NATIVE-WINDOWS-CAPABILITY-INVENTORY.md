# ERP ترنم — Capability Inventory (Current server/web product)

> الحاق ADR بومی: [`NATIVE-WINDOWS-DESKTOP-ARCHITECTURE.md`](./NATIVE-WINDOWS-DESKTOP-ARCHITECTURE.md)  
> استخراج از کد (۱۴۰۵/۰۷/۰۵): ۸۱ route · ~۸۸۰ endpoint · ۲۱۳ جدول · ۱۷۱ syncable · ۶۲ `centralOnly*`  
> این ماتریس **وضعیت فعلی سرور/وب** است؛ ستون «معادل بومی WPF» در موج‌های مهاجرت پر می‌شود.

**Evidence base:** `server/server.js` (lines 429–620 = router mount table), 81 files in `server/routes/`, ~880 `router.*` endpoints, 213 `CREATE TABLE IF NOT EXISTS` definitions across `server/`, 171 entries in `server/sync/tables.js`, `docs/PROJECT-HANDOFF.md`, `docs/OFFLINE-SYNC.md`, `docs/DESKTOP-OFFLINE-MODULE-MATRIX.md`, `server/public/acc-nav.js` (13 accounting sections / ~130 nav pages), `server/public/app.js` (`NAV_ADMIN` / `NAV_SALES` / `NAV_ACCOUNTING` / `ACC_NAV` / `ROUTES`).

**Legend for وابستگی شبکه؟ (network dependency):**
- `خیر` = fully local; the embedded server + local SQLite satisfies it.
- `sync` = works offline, but a globally-correct effect (final number, shared stock, cross-device visibility) only lands after central replay.
- `مرکز` = `centralOnly` (403 on device builds; desktop is partially exempt per `docs/DESKTOP-OFFLINE-MODULE-MATRIX.md`).
- `مرکز-سخت` = `centralOnlyStrict` (central only, no desktop exemption).
- `بیرونی` = real third-party service; no honest success without a live response.

## نکته‌های معماری مهم برای دسکتاپ Native

1. **Numbering is central-only by design.** فاکتور/خرید فقط از `allocateNumber()` روی `number_sequences`؛ آفلاین `موقت-…` + واترمارک. هر کلاینت native باید همین قرارداد را بپذیرد (`docs/PROJECT-HANDOFF.md` §۲، `OFFLINE-SYNC.md` اصل ۴).
2. **Multi-company = یک فایل DB مستقل به‌ازای هر شرکت**، نه `company_id` روی ردیف‌ها. تعویض شرکت یک عملیات سراسری است: revoke همهٔ سشن‌ها → `setActiveCompanyId` → `reopenDatabase` + `initDB`، با rollback اتمیک. مرجع: `server/routes/companies.js`, `server/lib/company-workspace.js`, `server/lib/company-switch-guard.js`.
3. **۶۲ endpoint با `centralOnly`/`centralOnlyStrict`** گیت شده‌اند (`server/middleware/auth.js:164-201`). `centralOnly` روی دسکتاپ (`APP_PLATFORM=desktop`) استثنا دارد؛ `centralOnlyStrict` ندارد — یعنی backup/restore، API keys، 2FA، data-wipe، AI، مودیان، Excel commit-import و دعوت کاربر در هر حالت فقط مرکز می‌مانند.
4. **Frontend امروز تک‌فایل/تک‌باندل است** (`server/public/index.html` + `app.js` حدود ۲۴هزار خط + `acc-nav.js`). ناوبری در سه آرایه (`NAV_ADMIN`, `NAV_SALES`, `NAV_ACCOUNTING`) به‌علاوهٔ `ACC_NAV_SECTIONS` با ۱۳ بخش و ~۱۳۰ صفحه که با `registerAccNavRoutes()` به `ROUTES` تزریق می‌شوند. زنجیرهٔ افزودن صفحه: nav item → `ROUTES['acc-X']` → `ACC_NOFILTER_TABS` → `case` در `loadAccTab` → `renderXTab()`.
5. **Zero external CDN** — فونت وزیرمتن، Chart.js و html2canvas از `server/public/vendor/` سرو می‌شوند (`PROJECT-HANDOFF.md` §۶-الف)، پس رندر کامل آفلاین از قبل تأمین شده.
6. **هر endpoint mutating باید در `PATH_TABLE_MAP` (`server/sync/capture.js`) ردیف داشته باشد** وگرنه outbox با `entity_table=null` می‌سازد و remap خراب می‌شود (`.cursor/rules/sync-hygiene.mdc`). این محدودیت برای هر مسیر جدیدی که کلاینت native اضافه کند هم برجاست.
7. **دو مسیر که روی یک prefix سوار شده‌اند:** `server.js:577-578` هم `procurement.js` و هم `purchases.js` را روی `/api/purchases` mount می‌کند (procurement اول). هر بازنویسی مسیر باید این ترتیب را حفظ کند.
