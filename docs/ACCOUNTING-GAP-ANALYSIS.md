## ۰. آخرین وضعیت برنامه (بررسی‌شده)

آخرین تغییرات مرورشده: ریبرند به **ERP ترنم/erp-taranom**؛ **یکپارچه‌سازی کامل واحد پول ریال** (UI و ذخیره ریال، `postToLedger` تومان می‌گیرد)؛ لایهٔ **inventory_ledger** سازمانی (لایه‌های بهای تمام‌شده، batch/serial، رزرو، landed cost)؛ حذف/ابطال گروهی؛ رد تکراری اکسل. **رفع باگ drift موجودی انبار (Claude) هم سالم است.**

### آنچه برنامه از قبل قوی دارد (Cursor اینها را دوباره نساز)
- **دفترداری دوطرفه** کامل: `journal_entries`/`journal_lines` + `createJournalEntry(db,{date,description,ref_type,ref_id,created_by,lines})` + دفاتر معین مشتری/تأمین‌کننده/شخص.
- **کدینگ ۴ سطحی محک** + لایهٔ نگاشت `server/lib/coa-map.js` با کلیدهای آمادهٔ فراوان (نمونه: `coa_cheques_receivable`=۱۱۰۹ اسناد دریافتنی، `coa_vat_payable`/`coa_vat_receivable`، `coa_severance_expense`، `coa_eidi_expense`، `coa_employer_insurance_expense`، `coa_sso_payable`، `coa_inventory_loss/gain`، `coa_abnormal_waste`، `coa_wip`، `coa_overhead_control/applied`، حساب‌های انحراف). **یعنی بیشتر حساب‌ها موجودند؛ آنچه نیست، فرآیند/گزارشی است که از آنها استفاده کند.**
- **ارزیابی موجودی**: FIFO + میانگین موزون متحرک + شناسایی ویژه (`lib/inventory/costing.js`) — استاندارد ۸ رعایت شده (لایفو نیست). ✅
- **بهای تمام‌شده تولید**: ماژول کامل (`production-*`, `lib/production/*`): BOM، WIP، جذب سربار، انحرافات (نرخ/کارایی/حجم/بودجه)، سفارش‌کار/مرحله‌ای، پیمانکاری جزء. ✅
- **فروش/ارزش افزوده پایه**: `calcDocTotals` (VAT ۱۰٪ روی خطوط مشمول، `vat_exempt`، `vat_class` کالا)، برگشت از فروش، تخفیف. ✅
- **حقوق**: `payroll_tax_brackets` (پلکانی ماده ۸۵)، سهم کارفرما (`employer_insurance_bp` پیش‌فرض ۲۳)، محاسبهٔ **عیدی و سنوات پایان سال** (`payroll_year_end_bonuses`)، batch ماهانه. ✅ (نواقصش پایین‌تر)
- **گزارش سنی مطالبات (Aging)** `GET /api/adv-reports/aging` ✅ · **گردش سال مالی** با انتقال سود انباشته/افتتاحیه ✅ · **انبارگردانی** ✅ · **تراز آزمایشی/ترازنامه/سود و زیان** ✅ · **مراکز هزینه** ✅ · **دارایی ثابت + استهلاک خط مستقیم** ✅.

|---|---|---|

**راهکار برای Cursor:** ماژول `routes/moadian.js` را از mock به یک صف واقعی با آداپتر API سازمان (قابل‌جایگزین) ارتقا بده؛ فیلدهای `moadian_invoice_type`, `products.tax_stuff_id`, `buyer_economic_code` روی فاکتور/مشتری اضافه کن (ensureColumn)؛ گزارش‌های `GET /api/reports/vat-return?quarter=` و `GET /api/reports/seasonal-169?quarter=` بساز که از `journal_lines` روی حساب‌های `coa_vat_*` و فاکتورها تجمیع کنند.

## ۹. نقشهٔ راه پیشنهادی برای Cursor (به ترتیب اولویت)

**فاز ۱ — انطباق قانونی 🔴 (بحرانی):**
1. سامانه مودیان واقعی: انواع صورتحساب (۱/۲/۳) + شناسهٔ کالا + آداپتر API + وضعیت روی فاکتور.
2. گزارش اظهارنامهٔ فصلی ارزش افزوده (ستانده − اعتباری) + صورت معاملات فصلی ماده ۱۶۹.
3. صورتحساب اصلاحی/ابطالی هماهنگ با برگشت‌ها.

**فاز ۲ — صورت‌های مالی استاندارد 🟠:**
4. صورت جریان وجوه نقد سه‌بخشی (استاندارد ۲).
5. اندوختهٔ قانونی ۵٪ + ذخیرهٔ مطالبات مشکوک‌الوصول + ذخیرهٔ کاهش ارزش موجودی (NRV).
6. صورت مغایرت بانکی + چرخهٔ کامل چک (در جریان وصول/برگشت/تعویض).

**فاز ۳ — تکمیل ماژول‌ها 🟠:**
7. دارایی ثابت: استهلاک نزولی + واگذاری/اسقاط + (تجدید ارزیابی).
8. حقوق: ذخیرهٔ ماهانهٔ سنوات/عیدی + مزایای الزامی + ضرایب اضافه‌کاری/شب‌کاری + سقف بیمه.
9. انبار: ذخیرهٔ NRV + گزارش کالای راکد + اطمینان از سند کسری/اضافات.

**فاز ۴ — مدیریتی 🟢:**
10. ماژول بودجه (جامع/نقدی/انحراف) + داشبورد KPI + نسبت‌های مالی + پکیج گزارش مدیریت + CVP.

## ۱۰. قواعد مخزن (Cursor حتماً رعایت کند)

- بک‌اند Node/Express + better-sqlite3؛ **بدون DB/ORM/فریم‌ورک جدید.** جدول‌ها در `db.js`→`initDB()` (idempotent) + `ensureColumn`.
- هر سند مالی از `createJournalEntry` رد شود تا تراز بماند؛ کد حساب از `coa-map.acct(db,key)` (نه کد ثابت). کلیدهای لازم که نیستند را به `LEGACY` در `coa-map.js` اضافه کن (مثل `coa_cheques_in_collection`, `coa_legal_reserve`, `coa_doubtful_debts`, `coa_inventory_writedown`, `coa_revaluation_surplus`).
- پول **ریال صحیح**؛ تاریخ جلالی رشته‌ای؛ timestamp epoch؛ PK صحیح.
- جدول‌های جدید → انتهای `sync/tables.js` (**APPEND-ONLY**) تا آفلاین‌سازی نشکند؛ سطوح پیکربندی مالیاتی با `centralOnly`.
- فرانت تک‌فایل `index.html` (الگوی `ROUTES`/`acc-nav.js`/`renderXxxTab`)؛ فایل JS جدا حتماً IIFE-wrap.
- عملیات چندجمله‌ای در `db.transaction`؛ شماره اسناد از `number_sequences`.
- **بعد از هر تغییر:** به‌روزرسانی Help (`renderAdminGuide`/`renderSalesGuide`) + ورودی `docs/CHANGE-LOG.md` + سبز ماندن `test-sms`/`test-sync`/`test:production` + تست جدید برای هر ماژول مالی.

> **جمع‌بندی:** پایهٔ دفترداری، کدینگ و بهای تمام‌شدهٔ برنامه قوی است؛ شکاف اصلی در **انطباق مالیاتی (مودیان/ارزش افزوده/۱۶۹)**، **صورت‌های مالی استاندارد (جریان نقد/اندوخته/ذخایر)**، **خزانه (مغایرت بانکی/چرخهٔ چک)** و **ماژول بودجه/گزارش مدیریتی** است. حساب‌های لازم عمدتاً در `coa-map` آماده‌اند؛ کار Cursor ساختن فرآیند و گزارش روی همان حساب‌هاست.
